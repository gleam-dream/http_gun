## Observation experiment

The downstream symptom is concrete: at `llm_wire/internal/http_client.gleam:72–77`, `owner.request_was_sent` is invoked inside the response callback. It therefore records response-header arrival rather than earlier local submission. Ordinary REST/long-poll services also benefit from separating admission wait from response latency. Application-side call timing can measure the total but cannot recover those internal milestones.

Gun2.6 `gun.erl:706–717` validates inputs, makes a reference, casts a request and returns. That establishes only return from a local asynchronous invocation. It does not prove Gun processed the cast, bytes were written successfully, the server received them or an application effect happened. `gun_http.erl:740–744` invokes its request-headers callback after a send attempt before checking the send result. Supported Gun callbacks are useful evidence but cannot be relabeled as successful transmission across all protocols. The exact selected files are hashed in the [experiment receipt](evidence/wave21/observation-receipt.json).

The disposable Gleam probe compares two storage mechanisms at capacity64 with six synthetic lifecycle marks per request. It runs in `/private/tmp/http-gun-observation-wave21`; no experiment code is imported into production or added to the ordinary gate. Timestamps are synthetic stage values, not measurements of real HTTP. A barrier pauses the ring consumer; there are no timing sleeps.

The first design retains a bounded list while its mailbox grows with traffic. It is unsuitable without an additional ingress contract. The fixed-slot probe overwrites old generations and uses one atomic compare-and-replace attempt for each notice. Failure drops the observation rather than waiting on a reader. It retains at most six typed marks in each of64 rows; there are no free-form metadata values or per-chunk events. Sixty-four synchronized contenders reading the same old value produce one successful commit and63 losses. Stale generations cannot change replacements, duplicate terminal updates do not replace the first terminal, reordered arrival retains distinct stage times, and a dead storage owner produces Stopped. A throwing reader does not stop later writes. Scripts/playback suppress the synthetic Gun-return mark; recording follows the live path, with capture outcomes absent from HTTP marks.

This validates the storage mechanism at these inputs, not a ready observation API. The temporary13-line Erlang bridge exposes ETS primitives and mailbox measurements; no production bridge was added. The selected Gleam Erlang/OTP libraries do not supply this typed compare-and-replace store. Before adopting one, review maintained ETS libraries against its precise semantics, or justify a minimal typed bridge. Successful bounded storage is not itself a reason to ship a larger public surface.

The remaining design must specify opaque invocation identity separately from a caller's correlation tag; a client epoch; monotonic VM-local event time; finite loss/cursor reporting; and who assigns each authoritative mark. Admission entry/wait/grant belong to the pool, while Gun-call return, final headers and HTTP termination belong to existing request/body owners. Only the owner settling HTTP may report its terminal outcome. Arrival order from different processes cannot stand in for request causality. Pre-validation/expired requests can have no observations, so absence never implies NotSubmitted. Retention loss and storage failure must not change HTTP or recording outcomes.

That experiment's pull-inspection candidate is superseded by the owner's 2026-10-01 decision to use Sinal. Its measurements remain historical; no fixed-slot production store is planned. The accepted responsibility split is in [DESIGN.md](DESIGN.md#accepted-sinal-observation-boundary-2026-10-01). HTTP Gun uses direct forwarding to an explicitly configured Sinal forwarder, avoiding synchronous fallback in critical actors. Delivery remains best effort, unsuitable for correctness/retry decisions; HTTP and recording outcomes remain independent. No network integration, end-to-end timing overhead or live event ordering was established by the earlier storage experiment.
